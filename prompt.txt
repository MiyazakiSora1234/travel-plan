# GitHub Actions CI/CD構成のレビュー・修正依頼

対象リポジトリ：

`https://github.com/MiyazakiSora1234/travel-plan.git`

## 目的

現在のCI/CDを、以下の設計思想に沿って実際に動作する状態へ修正してください。

### 基本方針

* `main` ブランチへのpushで本番デプロイ
* GitHub Actionsでテスト → Docker Image build → GHCR push → EC2 deploy
* EC2ではDocker Imageのbuildを行わない
* EC2はGHCRから完成済みImageをpullして起動するだけ
* Docker Imageには必ずGit commit SHAをタグとして付与する
* `latest` は補助的に付与してよいが、本番デプロイには使用しない
* Health Check成功後のみデプロイ成功とする
* Health Check失敗時は直前のImage SHAへ自動ロールバックする
* 本番の秘密情報 `.env` はEC2上だけに配置し、GitHub Actionsから作成・上書きしない
* EC2にはリポジトリ全体をcloneしない
* EC2には本番実行に必要なファイルだけをGitHub ActionsからSCPで配置する
* `compose.prod.yml` やPostgreSQL初期化スクリプトなど、本番構成に必要なファイルはGitリポジトリで管理する

EC2上は最終的に以下のようにする。

```text
/opt/travel-plan/
├── compose.prod.yml
├── .env
├── CURRENT_IMAGE_TAG
└── docker/
    └── postgres/
```

### Git管理

以下はGitで管理する。

```text
compose.prod.yml
docker/postgres/initdb/*
.env.prod.example
.github/workflows/*

```

### Git管理しない

以下は絶対にGitへコミットしない。

```text

*.pem
*.key
DBパスワード
GHCR等の認証情報
```

# 重要：現在のdeploy.ymlの問題を修正する

現在のdeploy処理では、SSHでEC2へ接続した後に、

```bash
scp compose.prod.yml ec2:/opt/travel-plan/
scp -r docker/postgres/initdb ec2:/opt/travel-plan/docker/postgres/
```

としている。

これは誤り。

SSH接続後のEC2上には、GitHub Actions runnerのリポジトリファイルが存在しないため、EC2からscpするのではなく、**GitHub Actions runnerからEC2へSCPすること。**

したがって、以下の2段階に分ける。

```text
GitHub Actions runner
        │
        │ SCP
        ▼
      EC2
        │
        │ SSH
        ▼
docker compose pull/up
Health Check
```

GitHub Actionsでは `actions/checkout@v4` を使用してリポジトリを取得し、その後 `appleboy/scp-action` 等を利用して必要なファイルだけをEC2へ転送する。

---

# Deploy Jobの要件

`deploy` jobは以下の順番にする。

```text
1. checkout
2. production用ファイルをEC2へSCP
3. SSHでEC2へ接続
4. GHCRへログイン
5. 現在稼働中のIMAGE_TAGを保存
6. 新しいIMAGE_TAGをexport
7. docker compose pull
8. docker compose up -d
9. Health Check
10. 成功 → CURRENT_IMAGE_TAG更新
11. 失敗 → PREV_TAGへロールバック
12. docker logout
```

# GitHub Secrets

以下を利用する。

```text
EC2_HOST
EC2_USER
EC2_SSH_KEY
```

意味：

```text
EC2_HOST      = EC2のホスト/IP
EC2_USER      = ec2-user
EC2_SSH_KEY   = SSH秘密鍵PEMの中身
```

GitHub Actionsの `GITHUB_TOKEN` はGHCRへの認証に使用する。

追加のGHCR用長期Secretは可能な限り作らない。

# GitHub Variables

Frontendのビルド時に必要なAPI URLはRepository Variablesを使用する。

```text
VITE_API_BASE_URL
```

例：

```text
http://52.199.123.9:8080
```

これは機密情報ではないためSecretにはしない。

Viteの仕様上、ビルド時に値がFrontend bundleへ埋め込まれることを考慮すること。

# Docker Image

Image名は以下。

```text
ghcr.io/miyazakisora1234/travel-plan/backend
ghcr.io/miyazakisora1234/travel-plan/frontend
```

タグ：

```text
${{ github.sha }}
```

および補助的に、

```text

```

を付与する。

ただし本番Deployでは必ず、

```text
:${{ github.sha }}
```

を利用する。

# compose.prod.yml

`compose.prod.yml` はGit管理する。

Image指定は必ずIMAGE_TAGを利用する。

例：

```yaml
services:
  backend:
    image: ghcr.io/miyazakisora1234/travel-plan/backend:${IMAGE_TAG}

  frontend:
    image: ghcr.io/miyazakisora1234/travel-plan/frontend:${IMAGE_TAG}
```

実際のリポジトリ構成を確認し、既存の設定を壊さないように修正する。

# 本番.env

EC2上に、

```text
/opt/travel-plan/.env
```

を手動で作成する。

例：

```env
POSTGRES_DB=travel_plan
POSTGRES_USER=postgres
POSTGRES_PASSWORD=<実際の強力なパスワード>

APP_DB_USER=travel_plan_app
APP_DB_PASSWORD=<実際の強力なパスワード>

DATABASE_URL=jdbc:postgresql://postgres:5432/travel_plan

CORS_ALLOWED_ORIGINS=http://52.199.123.9

SERVER_PORT=8080
```

ただし、実際のSpring Boot / Docker Composeの設定を確認し、環境変数名が一致していることを確認する。

`.env` の実値は絶対に生成・コミットしない。

`IMAGE_TAG` は `.env` に保存せず、Deploy Jobからexportする。

# Health Check

Backendの、

```text
http://localhost:8080/actuator/health
```

を利用する。

最大60秒、

```text
5秒 × 12回
```

リトライする。

以下を確認する。

```json
{"status":"UP"}
```

単に、

```bash
docker compose up -d
```

が成功しただけではDeploy成功にしない。

---

# ロールバック

Deploy前に、

```bash
PREV_TAG="$(cat CURRENT_IMAGE_TAG 2>/dev/null || true)"
```

で現在のImage SHAを取得する。

新ImageのHealth Checkに失敗した場合、

```bash
export IMAGE_TAG="$PREV_TAG"
docker compose -f compose.prod.yml up -d
```

で直前のImageへ戻す。

成功した場合のみ、

```bash
echo "$IMAGE_TAG" > CURRENT_IMAGE_TAG
```

を実行する。

# セキュリティ要件

以下を必ず守る。

* `.env` をGit管理しない
* `.pem` をGit管理しない
* GitHub Actionsのログへ秘密情報を出力しない
* `GITHUB_TOKEN` をechoしない
* GHCR logoutを実施する
* PostgreSQLの5432をSecurity Groupで外部公開しない
* SSH 22番は可能な限り接続元を制限する
* CORSに `*` を使用しない
* Docker build contextに`.env`等の秘密情報が入らないよう`.dockerignore`を確認する
* 長期的なGHCR Personal Access TokenをEC2へ保存しない

# 実装上の注意

単純に既存コードを書き換えるのではなく、まず現在のリポジトリ構成を確認すること。

既存の設計を尊重し、不要な変更は行わない。

特に、

```text
EC2上でscp
```

ではなく、

```text
GitHub Actions runner
    ↓
SCP
    ↓
EC2
```

になっていることを確認する。

また、Deploy Workflow全体がGitHub ActionsのYAMLとして構文的に正しく、`needs` によるJob依存関係が正しく機能することを確認する。

最終的に、

```text
push main
 ↓
test
 ↓
build & push GHCR
 ↓
SCP production files
 ↓
SSH EC2
 ↓
GHCR login
 ↓
docker compose pull
 ↓
docker compose up -d
 ↓
Health Check
 ├─ UP → CURRENT_IMAGE_TAG更新
 └─ NG → PREV_TAGへrollback
```

という流れになるように実装してください。

最後に、変更したファイル一覧と、それぞれの変更理由、GitHub側で必要なSecrets/Variables、EC2で初回だけ実行するコマンドをまとめてください。
